# Clinic OS Workspace Rules

The root [`AGENTS.md`](../../AGENTS.md) is the canonical source for product invariants, architecture, database contracts, and verification requirements. Read it before changing code; do not duplicate or override its rules here.

For repository changes, run `flutter analyze` and `flutter test`. Keep changes within the clinical workflow and product boundaries in `AGENTS.md`. Always enforce Indian date format (`DD-MM-YYYY`) across all UI text, printed prescriptions, changelogs, and markdown documentation. Enforce Single-Occupant Chamber Integrity (zero pre-emption of active tokens). Enforce strict 3-Column Isolation on prescription tables (Col 1: Medicine `Brand [COMPOSITION]` in UPPERCASE; Col 2: Dosage & Timing; Col 3: Duration `To Continue`/`X Days`/`To STOP`; no `[NEW]` badges and zero mixing). In `CHANGELOG.md`, never add Verification Gate/test execution sections, and always consolidate patch releases into minor series range entries (e.g. `[1.4.0 – 1.4.5]`) when jumping versions to keep documentation concise. Backward compatibility is NOT required (never add shims or legacy glue); always inform the PM if a breaking change is introduced.
