# Maintenance Guide

This project is **100% AI-maintained**. Code changes, bug fixes, and feature additions are handled exclusively by AI agents. Human involvement is limited to configuration and content.

---

## What Humans Configure

These are the only files / values humans are expected to edit directly:

### `lib/utils/app_constants.dart`

```dart
static const int defaultConsultationFee = 500; // ← Change the consultation fee here

static const List<String> blockedDates = [
  '2026-10-02', // ← Add/remove clinic holiday dates (YYYY-MM-DD)
];
```

### `pubspec.yaml`

- `version` — bump when releasing a new build
- `name` / `description` — if rebranding

### `lib/firebase_options.dart`

- Generated by `flutterfire configure`. Re-run this command if changing Firebase projects.
- **Never commit this file to git.**

### `assets/`

- Replace `icon.png` to change the launcher icon.

---

## For AI Agents

When making code changes:

1. Run `flutter analyze` — zero warnings required before committing.
2. Run `dart format .` — all files must be formatted.
3. Update `CHANGELOG.md` under `[Unreleased]` with a concise entry.
4. Keep model classes (`lib/models/`) free of Firebase/Flutter SDK imports.
5. All Firestore read/write goes through `FirebaseService` only.
6. Do not add `// TODO`, dev-session markers (`// NEW:`, `// <---`), or uppercase section labels (`// HEADER ROW`) — the code is self-documenting.
7. `AppConstants.defaultConsultationFee` is the single source of truth for the fee — never hardcode `500`.

### Architecture Rules

```
models/       ← pure Dart, no external dependencies
services/     ← all Firestore logic lives here
providers/    ← state management (ChangeNotifier), delegates to services
screens/      ← UI only, reads from providers and services
utils/        ← constants and stateless helpers
```
